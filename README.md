# Путь (The Way)

Мобильное приложение — аналог BlaBlaCar для малых городов России: пассажиры онлайн бронируют места
в поездках между населёнными пунктами, водители публикуют поездки и подтверждают пассажиров.

Состав: мобильное приложение на Flutter (Android; iOS-проект тоже есть) и REST API на NestJS с PostgreSQL. Сервер развёрнут и работает.

## Как попробовать

1. Установите APK на Android-телефон (или запустите `flutter run`, см. ниже) — приложение по умолчанию
   ходит на стенд.
2. Войдите по **любому** номеру телефона, код подтверждения — **`111111`** (SMS не отправляются).
   Новый номер — новый пользователь: онбординг, город, имя, фото, роль.
3. Готовые пользователи с данными (тот же код `111111`):

| Номер | Кто | Что у него есть |
| --- | --- | --- |
| `+79000000001` | водитель Алексей | два автомобиля и сохранённый маршрут, поездок нет — для публикации своей |
| `+79000000002` | водитель Мария | поездки на ближайшие дни, завершённые поездки с отзывами, жалоба от пассажира (профиль → «Жалобы») |
| `+79000000003` | водитель Дмитрий | поездки на ближайшие дни (в том числе быстрое бронирование и посылки), завершённые поездки с отзывами |
| `+79000000004` | водитель Сергей | автобус ГАЗель Next на 24 места и поездки на нём на ближайшие дни — вкладка поиска «Автобусы» |
| `+79000000005` | водитель Николай | автобус ПАЗ Vector Next на 30 мест и поездки на нём Ярославль → Углич на ближайшие дни — вкладка поиска «Автобусы» |
| `+79000000006` | водитель Игорь | Toyota Camry, поездки Рыбинск → Тутаев → Ярославль утром (07:30) на ближайшие дни, завершённые поездки с отзывами (4,9 — плашка «Топ») |
| `+79000000007` | водитель Елена | Volkswagen Polo, быстрое бронирование, поездки Ростов → Переславль-Залесский около 11:00 на ближайшие дни, завершённые поездки с отзывами (4,9 — плашка «Топ») |
| `+79000000008` | водитель Роман | Skoda Rapid, поездки Углич → Ярославль после обеда (14:00) на ближайшие дни, завершённые поездки с отзывами (4,0) |
| `+79000000011` | пассажир Иван | броней нет — для сценария «найти и забронировать» |
| `+79000000012` | пассажир Ольга | брони во всех статусах и одна отмена |

Поездки водителей `+79000000002`…`+79000000008` сервер пополняет каждую ночь, чтобы в поиске всегда были поездки на
ближайшие дни. Лента поиска идёт по рейтингу водителя (водители без отзывов — после водителей с отзывами), затем по времени выезда; у Дмитрия, Игоря и Елены он один (4,9), поэтому
на первом экране — поездки этих трёх водителей вперемешку.

Один аккаунт — обе роли: режим переключается в профиле («Перейти в режим водителя» / «…пассажира»).

Встречный заказ: пассажир, не нашедший поездку, публикует заказ («+» внизу в режиме пассажира —
маршрут, дата, места или посылка, услуги, без цены); водитель видит его во вкладке «Заказы пассажиров»
ленты и откликается своей поездкой или новой — у пассажира появляется бронь «Ожидает оплаты».

Ответы второй стороны (заявка принята, отклонена, оплачена, отклик на заказ) приложение проверяет при
открытии и каждые 30 секунд, пока оно на экране.

## Запуск приложения

Нужны Flutter 3.47 (Dart 3.13) и Android SDK.

```sh
cd apps/mobile
flutter pub get
flutter run
```

Без параметров приложение работает со стендом `https://theway.dabooke.com`. Свой сервер —
`flutter run --dart-define=API_URL=<адрес>`; для API на этой же машине из эмулятора Android —
`--dart-define=API_URL=http://10.0.2.2:3000`.

Release-сборка APK: `flutter build apk --release` (из `apps/mobile`).

iOS: нужен Mac с Xcode и Flutter; `flutter run` из `apps/mobile` с подключённым iPhone или
запущенным симулятором. CocoaPods не нужен — плагины подключаются через Swift Package Manager;
минимальная версия — iOS 15.

## Запуск сервера локально

Нужны Node.js 24 и Docker.

```sh
docker compose up -d          # PostgreSQL 18 на localhost:5433
npm ci
```

Переменные окружения API — имена в [`.env.example`](.env.example); сервер читает их из окружения
процесса. Минимум для локального запуска — `DATABASE_URL` (база `postgres` контейнера: пользователь и
пароль `postgres`, порт `5433`); `PORT` — по умолчанию `3000`; `APP_TZ` — по умолчанию `Europe/Moscow`;
`MAPBOX_TOKEN` необязателен (без него подсказок адреса нет, адрес вводится строкой).

```sh
# bash
export DATABASE_URL=postgres://postgres:postgres@localhost:5433/postgres
# PowerShell
$env:DATABASE_URL = 'postgres://postgres:postgres@localhost:5433/postgres'
```

```sh
npm run db:migrate     # схема
npm run db:seed        # демо-данные (очищает таблицы и заливает заново)
npm run dev            # API на http://localhost:3000, Swagger UI — /docs
```

Продовая сборка API: `npm run build`, запуск — `node apps/api/dist/main.js` (миграции применяются при
старте). Пополнение демо-поездок без очистки — `npm run db:seed:demo`.

## Тесты

```sh
# API: модульные и интеграционные наборы, нужна база (отдельная от демо-данных)
export DATABASE_URL=postgres://postgres:postgres@localhost:5433/dev_1
npm test

# Приложение
cd apps/mobile
flutter analyze
flutter test
```

Контейнер PostgreSQL при первом старте создаёт пустые базы `dev_1` … `dev_6` — под тесты.

## Структура репозитория

| Путь | Что |
| --- | --- |
| `apps/api` | сервер: NestJS, Drizzle ORM, миграции (`drizzle/`), демо-данные (`seed/`), тесты (`test/`) |
| `apps/mobile` | приложение: Flutter, экраны по разделам (`lib/src/features/`), тема (`lib/src/theme/`), строки (`lib/l10n/app_ru.arb`) |
| `contracts/openapi.json` | контракт API, порождается кодом сервера |
| `packages/api-client-dart` | Dart-клиент API, порождается из контракта |
| `design/tokens` | токены цвета и типографики, снятые с макета |
| `deploy` | конфигурация стенда: pm2, nginx, обновление, ночное пополнение демо-данных |
| `docker`, `docker-compose.yml` | PostgreSQL для разработки |
| `tools/data` | сборка справочника марок и моделей автомобилей |

## Упрощения тестового задания

- **SMS** не отправляются: код подтверждения везде `111111`.
- **Оплата** не подключена: «Оплатить» сразу переводит бронь в «Оплачено»; возврат денег при отмене —
  только запись и экран с суммой.
- **Отзывов** в интерфейсе нет: без отзывов показывается «5, нет отзывов». Таблицы отзывов, жалоб,
  блокировок и проверок администратора в базе есть; рейтинг считается по отзывам (в демо-данных отзывы есть).
- **Push-уведомлений** нет: ответы второй стороны (заявка принята, отклонена, оплачена) показываются
  экранами при открытии приложения и при проверке раз в 30 секунд, пока приложение на экране.
- **Чат** и **панель администратора** — вне объёма задания (подробности — в требованиях).
