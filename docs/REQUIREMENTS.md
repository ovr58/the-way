# Требования «Путь» (The Way) — как построено

Исходное задание — [`task.md`](task.md). Здесь — итоговые требования, по которым построены
приложение и сервер: роли, сценарии с критериями приёмки, функциональные и нефункциональные
требования, что сознательно не входит. Как это устроено — [`SPECIFICATION.md`](SPECIFICATION.md),
[`ARCHITECTURE.md`](ARCHITECTURE.md). Экраны макета — [`SCREENS.md`](SCREENS.md); отличия от
макета — [`DESIGN_CHANGES.md`](DESIGN_CHANGES.md).

## Цель

Мобильное приложение — аналог BlaBlaCar для малых городов России: пассажир находит и бронирует
место (или отправку посылки) в поездке на легковом автомобиле между населёнными пунктами,
водитель публикует поездку и подтверждает пассажиров. Сегодня «из одного села в другое» ходят
маршрутки, где всё аналоговое: прийти на место, найти водителя, договориться, ждать.

**Готово, когда** проверяющий на своём Android-устройстве вне России проходит сквозной сценарий
«регистрация → водитель создаёт поездку → пассажир находит и бронирует → водитель подтверждает →
пассажир „оплачивает“ → оба видят поездку в своих списках» без ручной помощи и без падений; сервер
работает; приложение также запускается командой `flutter run`.

## Роли

| Роль | Кто | Главная задача |
| --- | --- | --- |
| Пассажир | житель малого города, едет сам или отправляет посылку | найти поездку, забронировать место или посылку, «оплатить», видеть свои брони |
| Водитель | владелец легкового авто с регулярными рейсами | добавить авто, опубликовать поездку, принять или отклонить заявки, видеть свои поездки |
| Администратор | сотрудник сервиса | проверки фото и СТС, блокировки и жалобы — **только данные в базе**, интерфейса нет |

Один аккаунт — обе роли: режим переключается в профиле («Перейти в режим водителя» /
«…пассажира»). Нижняя панель одна — «Поездки · Мои заказы · Чаты · Профиль»; режим меняет
содержимое «Мои заказы» и пункты профиля.

## Объём

**Входит:**

- Онбординг (3 слайда), выбор города, вход по номеру телефона с кодом, создание профиля (имя,
  фото), выбор роли.
- Водитель: мои автомобили (добавить, редактировать, фото СТС и его замена, удалить); создание поездки мастером (тип →
  маршрут с остановками → дата и время → пассажиры → цена → авто → доп. услуги → тип бронирования
  → подтверждение); обратная поездка; сохранённые маршруты; лимиты публикаций; мои поездки
  (активные и завершённые); заявки (подтвердить / отклонить); изменение числа мест; завершение
  приёма пассажиров; отмена поездки; профиль пассажира.
- Пассажир: лента поездок (вкладки «Автомобили» / «Автобусы»), ранжирование, фильтр по
  населённым пунктам и «поблизости», детали поездки, бронирование места и/или посылки с доп.
  услугами, «оплата», отмена брони с правилами блокировки, «Мои заказы», экраны ответов водителя.
- Встречный заказ: пассажир публикует заказ без цены (маршрут, дата, места или посылка, услуги);
  водитель видит ленту «Заказы пассажиров» и откликается своей или новой поездкой — у пассажира
  бронь «Ожидает оплаты».
- Профиль: личные данные (имя и фото), рейтинг, полученные жалобы, смена режима, выход. Пункты
  «Сохранённые маршруты», «История заказов», «Уведомления», «Способ оплаты», «Частые вопросы»,
  «О приложении» (кадров в макете нет) ведут на общий экран «Раздел в разработке».
- Системные экраны: загрузка, нет интернета, ошибка действия, аккаунт заблокирован.
- Сервер с REST API и базой, где заложены таблицы отзывов, жалоб, блокировок и проверок
  администратора.

**Сознательно не входит:**

| Что | Почему |
| --- | --- |
| Отправка SMS | задание: сервис SMS не подключается, код везде `111111` |
| Онлайн-оплата | задание: «Оплатить» сразу переводит в «Оплачено»; возврат при отмене — запись и экран с суммой |
| Оставление отзывов | задание: функционала отзывов нет, показывается «5 звёзд, нет отзывов»; таблицы отзывов в базе есть, рейтинг считается по ним |
| Push-уведомления | ответы второй стороны показываются экранами внутри приложения при открытии и при проверке раз в 30 секунд — без внешней инфраструктуры |
| Чат | в макете только кнопки «Написать», экранов чата нет — кнопка ведёт на экран «Чат появится позже» |
| Панель администратора | в макете нет; авто считается проверенным сразу, блокировки и жалобы — записи в базе |
| Монетизация и комиссия | комиссия выключена, пассажир видит цену водителя целиком |
| Карты | в макете их нет; адрес — строка с подсказками, расстояния — по координатам адреса или города |
| Сборка под iOS | задание требует APK; проект iOS в репозитории есть и запускается `flutter run` на Mac, отдельно не проверялся проверяющим сценарием |
| Тёмная тема, языки кроме русского, офлайн-режим | в макете и задании нет |

## Сценарии и критерии приёмки

### US-01 — Пассажир находит и бронирует место

**Как** пассажир, **я хочу** найти поездку между нужными населёнными пунктами и забронировать
место, **чтобы** не искать маршрутку на месте.

- **Given** пассажир вошёл и выбрал город **When** открывает ленту «Поездки» **Then** видит
  карточки активных поездок, отсортированные по рейтингу водителя (водители без отзывов — после водителей с отзывами),
  затем по времени отправления;
  у одинаковых «маршрут + время» бронируема только первая («Идёт регистрация пассажиров»),
  остальные показаны без кнопки брони.
- **Given** лента **When** пассажир задаёт фильтр «откуда / куда» или «поблизости» **Then** список
  сужается; пустой результат — «Здесь ещё нет заказов».
- **Given** детали поездки со свободными местами **When** пассажир нажимает «Забронировать место»,
  выбирает число мест и доп. услуги, отправляет заявку **Then** при стандартном бронировании бронь
  ждёт водителя («Ожидает подтверждения»; у водителя — «Не подтвержден»), при быстром — сразу
  предлагает оплату.
- **Given** бронь ждёт оплаты **When** пассажир нажимает «Перейти к оплате» → «Оплатить» **Then**
  бронь «Оплачено», экран «Место забронировано», бронь видна в «Мои заказы».
- **Given** в поездке 0 свободных мест **When** пассажир открывает детали **Then** брони места нет
  («Мест нет»); доступна «Отправить посылку», если водитель её разрешил.

### US-02 — Водитель публикует поездку

**Как** водитель, **я хочу** опубликовать поездку с маршрутом, временем, ценой и условиями,
**чтобы** пассажиры нашли и забронировали места.

- **Given** у водителя нет авто **When** он доходит в мастере до шага «Авто» **Then** видит «Нет
  добавленных авто» и переходит в «Добавить авто».
- **Given** водитель заполнил мастер (маршрут от/до и остановки, дата и время с шагом 30 минут,
  число мест, цена за весь маршрут и между остановками, стоимость посадки, авто, доп. услуги, тип
  бронирования; календарь даёт выбрать только дни и время от текущего момента до +72 часов)
  **When** нажимает «Опубликовать» и подтверждает **Then** поездка активна, экран
  «Заказ опубликован!», она видна в ленте пассажиров.
- **Given** на это авто в эти сутки уже опубликованы поездка и обратная **When** водитель публикует
  ещё **Then** отказ с экраном лимита (1 поездка + 1 обратная в сутки, не дальше 3 дней вперёд).
- **Given** опубликованная поездка **When** водитель нажимает «Добавить обратный маршрут» **Then**
  создаётся поездка с маршрутом в обратном порядке, время задаётся заново.
- **Given** поездка без присоединившихся пассажиров **When** водитель редактирует или отменяет
  **Then** изменения сохраняются / поездка отменена без последствий.
- **Given** к поездке присоединился пассажир (заявка принята) **When** водитель открывает
  редактирование **Then** маршрут, время и цену менять нельзя («Редактирование недоступно»);
  доступны «Изменить количество мест» (не меньше занятых) и «Завершить приём пассажиров».

### US-03 — Водитель управляет заявками

**Как** водитель, **я хочу** видеть заявки пассажиров и подтверждать или отклонять их, **чтобы**
контролировать, кто едет.

- **Given** стандартное бронирование и новая заявка **When** водитель открывает приложение или
  поездку **Then** видит окно «Пришёл отклик», счётчик откликов, профиль пассажира (имя, фото,
  рейтинг, его маршрут, число мест, доп. услуги) и кнопки «Подтвердить бронь» / «Отклонить бронь».
- **Given** водитель подтвердил **Then** бронь ждёт оплаты, у пассажира окно «Водитель принял
  заявку»; **Given** отклонил **Then** бронь «Отклонена», у пассажира «Водитель отклонил заявку».
- **Given** пассажир «оплатил» **Then** у водителя окно «Пассажир оплатил поездку», свободных мест
  меньше, бронь «Подтверждён».

### US-04 — Отмена и правила сообщества

**Как** участник, **я хочу** отменить бронь или поездку, **чтобы** не ехать, — и понимать
последствия.

- **Given** заявка, которую водитель ещё не принял («Ожидает подтверждения») **When** пассажир её
  отменяет **Then** окно «Отменить заявку?» без счётчика; заявка отменена и в счёт отмен не идёт.
- **Given** принятая бронь (ждёт оплаты или оплачена), отмен за 30 дней не было **When** пассажир
  отменяет **Then** окно «Отменить бронирование?» с предупреждением «Две отмены в течение 30 дней
  приведут к автоматической блокировке» и счётчиком «0 / 2»; у оплаченной — строки «Возврат на
  карту», «Срок зачисления до 3 дней» и после отмены экран «Бронь отменена» с суммой возврата; у
  неоплаченной — подсказка «Бронь отменена».
- **Given** за 30 дней уже была одна отмена **Then** окно со счётчиком «1 / 2», затем второе окно
  «Это может повлиять на ваш аккаунт» с «Всё равно отменить».
- **Given** вторая отмена за 30 дней **Then** аккаунт блокируется на 30 дней — и бронирование, и
  публикация; экран «Аккаунт временно заблокирован», запись о блокировке в базе; у оплаченной брони
  после него — экран «Бронь отменена» с суммой возврата.
- Те же правила — для водителя при отмене поездки с присоединившимся пассажиром; его экран
  блокировки — «Публикация новых поездок временно недоступна».
- **Given** аккаунт заблокирован **When** пользователь бронирует или публикует **Then** экран
  «Аккаунт временно заблокирован».

### US-05 — Вход и профиль

- **Given** новый пользователь **When** проходит онбординг, выбирает город, вводит телефон и код
  `111111`, имя, фото и роль **Then** попадает в приложение в выбранном режиме.
- **Given** неверный код **Then** «Неверный код подтверждения» и таймер повторной отправки.
- **Given** профиль **When** пользователь меняет имя или фото, смотрит рейтинг и жалобы,
  переключает режим, выходит **Then** данные сохранены, режим переключён, сессия завершена.
- **Given** у пользователя нет отзывов **Then** в профиле и карточках — «5, нет отзывов», а если
  есть завершённые поездки — «5, нет отзывов • N поездок».

### Ошибки

| ID | Что пошло не так | Что делает система |
| --- | --- | --- |
| US-E1 | нет сети | экран «Нет интернет-соединения» с «Обновить» |
| US-E2 | сервер вернул ошибку или не ответил | экран «Не удалось выполнить действие» с повтором |
| US-E3 | аккаунт заблокирован администратором | экран «Ваш аккаунт заблокирован», действия недоступны |
| US-E4 | сессия истекла | возврат на экран входа |
| US-E5 | два пассажира бронируют последнее место | побеждает первый на сервере, второму — «Мест нет» |

| NFR-01 | Производительность | ответ API ≤ 500 мс на тестовых данных |
| NFR-02 | Объёмы | десятки пользователей, сотни поездок |
| NFR-04 | Безопасность | сессия по непрозрачному токену, в базе — хэш; чужие брони и поездки закрыты на сервере (404 / 403); ключи внешних сервисов — только на сервере |
| NFR-05 | Приватность | в базе только синтетические данные: телефон, имя, фото, фото СТС, геолокация в момент поиска; реальных пользователей нет |
| NFR-06 | Язык | только русский; строки — в ARB-файле, без литералов в виджетах |
| NFR-07 | Наблюдаемость | продуктовая аналитика не собирается; на сервере — структурный лог запросов с trace id, ошибки клиента пишутся в тот же лог |
| NFR-08 | Офлайн | не поддерживается; экран «Нет интернета» |
| NFR-09 | Запускаемость | APK и `flutter run` работают без параметров против развёрнутого сервера; сервер поднимается локально по шагам `README.md` |

## Критерии приёмки сдачи

- US-01…US-05 проходят на собранном APK против развёрнутого сервера.
- `flutter run` стартует приложение против того же сервера.
- APK и архив кода лежат на диске, ссылка открывается без входа.
- В базе есть таблицы отзывов, жалоб, блокировок и проверок администратора.
